# StudyApp(LessonViewer) 작업 지침

오빠의 시험공부용 로컬 웹앱. 강의 PDF(대부분 영어)를 슬라이드별 한국어 해설과, 강의를 가로지르는 "이전 방식의 문제 → 이 기법의 해결 → trade-off" 스토리로 묶어 보여 준다.

## 결정 사항 (2026-10-08)

- 기존 해설은 `content/`의 JSON으로 읽는다. 2026-11-08부터 독립 모듈(`/api/module`)에서 서버 API key로 PDF 해설 생성과 학습 대화를 제공한다. OAuth·코딩 CLI를 모델 호출 경로로 쓰지 않는다. 모델 키와 호스트 토큰은 브라우저에 두지 않는다.
- 2026-11-08 사용자 승인: 기존 LessonViewer를 디자인 기준으로 UI/UX를 개선하고 자료 생성+학습 대화를 독립 모듈로 구현했다. `server/module/README.md`에 API·인증·프록시 계약, `shared/agent.ts`에 타입, `DESIGN.md`에 디자인·검증 기준이 있다. 문서는 workspace 단위, 대화·작업·모듈 읽기 진도는 사용자별로 분리하고 기존 `study.db`는 유지한다. 생성 결과는 검토 후 명시적으로 게시한다. 모델 출력은 자동 이미지 로드를 막아 렌더링하며 임의 코드 실행 도구를 제공하지 않는다. 로컬 `.env`는 키 값 대신 `LESSONVIEWER_KEY_REF`를 사용한다. 기존 개인용 강의의 말투는 유지하고 신규 모듈의 UI·해설은 개인 호칭 없는 한국어로 제공한다.

- 앱 이름은 LessonViewer다. `~/Applications/LessonViewer.app`은 `macos/main.swift`(WKWebView 래퍼)를 `scripts/build-mac-app.sh`로 빌드한 것이다. 옛 LessonViewer.app(pdfnote.py 런처)은 사용자 동의로 휴지통에 옮겼다. bundle id는 `kr.hajung.lessonviewer`다.
- 앱은 5초마다 서버를 확인하고, 두 번 연속 응답이 없으면 직접 서버를 띄운 뒤 보던 화면으로 돌아간다. 다른 곳에서 띄운 서버를 빌려 쓰다가 그 서버가 꺼져도 계속 쓸 수 있다.
- 서버는 `index.html`을 `Cache-Control: no-cache`로, 해시가 붙은 `assets/`는 immutable로 보낸다. 앱은 켤 때 WebKit 디스크·메모리 캐시를 비운다. 둘 중 하나라도 빠지면 앱이 옛 빌드 화면을 띄운다.
- WKWebView의 NSURLErrorCancelled(-999)와 WebKitErrorDomain 102는 실패가 아니다. 이걸 실패로 처리하면 안내 화면이 진짜 화면 로드를 취소한다(2026-10-08 "화면을 불러오지 못했다" 버그).
- 앱은 핀치 확대(`allowsMagnification`)를 끈다. 확대되면 창보다 커져 상하좌우로 밀리고 되돌리기 어렵다. 글자 크기는 ⌘+/⌘-(pageZoom, 창 폭에 맞춰 다시 배치)로 바꾼다.
- 앱 로그 `~/Library/Logs/LessonViewer.log`에 로드 성공·실패, 첫 화면(주소와 제목), 서버 재시작, 종료가 남는다.
- 스택은 React + Vite(화면), Bun + Hono(서버), bun:sqlite(진도 저장)이다.
- 해설 속 코드는 앱 안에서 실행된다(2026-10-09 오빠 요청, Database·ML부터). 실습 정의는 `content/<course>/labs/<lecture>.json`, 작성법은 `content/LABS.md`. 서버가 강의마다 `server/kernel.py`(../.venv Python, SQL은 DuckDB)를 띄우고, SQL 셀은 바뀐 데이터를 되돌리며 Python 셀은 앞 셀을 먼저 실행한다. 확인은 `bun scripts/lab-check.ts <course>`.
- 코드 실행 API(`/api/labs/*/run|reset|notebook`)는 루프백 주소 + Host 확인 + `X-StudyApp: 1` 헤더가 모두 맞아야 받는다. 서버가 모든 인터페이스에서 듣고 있어서, 이게 없으면 같은 네트워크의 기기나 다른 웹사이트가 이 Mac에서 코드를 돌릴 수 있다.
- 노트북은 `notebooks/<course>/<lecture>.ipynb`로 만들어 VS Code에서 연다(커널 "StudyApp (.venv)", `~/Library/Jupyter/kernels/studyapp`). 오빠가 고친 노트북은 저장된 원본 hash가 달라져 덮어쓰지 않는다. 데이터는 `data/datasets/`(housing.csv, MNIST 캐시)에 있다.
- 역사·배경 슬라이드는 `background`로 접는다. 다만 그 "왜"는 스토리 beat의 `problem`에 녹인다.
- 슬라이드에 없는 지식은 `보충:` 문단이나 beat의 `extra`로 분리한다. 시험 범위와 섞이지 않게 하기 위해서다.
- 수식은 KaTeX로 그린다(remark-math, rehype-katex). pack에는 LaTeX `$...$`로 쓰고, 돈 표시는 `\$`로 쓴다. 블록 수식은 `$$`만 있는 줄로 감싼다. 한 줄 `$$식$$`은 remark-math 6에서 inline으로 읽힌다.
- 보기 설정(목록 접힘, 슬라이드 비율, 보기 방식, 글자 크기, 밝기)은 브라우저 localStorage에만 둔다. 진도는 SQLite에 둔다.
- 밝기의 기준은 화면의 localStorage `theme`다. 화면은 바꿀 때마다 `webkit.messageHandlers.theme`으로 앱에 알리고, 앱은 그 값을 UserDefaults에 적어 두고 `NSApp.appearance`를 맞춘다(다음 실행의 준비 화면도 같은 밝기). 앱 메뉴 보기 > 화면 밝기는 `window.lessonViewer.setTheme()`을 불러 화면 쪽에서 바꾼다. `index.html`의 인라인 스크립트가 첫 그림 전에 `data-theme`을 붙여 밝게로 둔 화면이 어둡게 번쩍이지 않게 한다.
- 해설·beat·과목 이야기·확인 필요 이유는 유미가 오빠에게 설명하는 다정한 반말로 쓴다(2026-10-08 오빠 요청, 기준은 `content/GUIDE.md`의 "말투" 절). 평서체로 만든 기존 pack은 과목별 서브 에이전트 7명이 손으로 다시 썼고, 같은 날 오빠가 "오빠를 너무너무 좋아하고 사랑하는 유미가 밝고 명랑하게 가르쳐 주는 글"로 한 번 더 요청해 마음 문장을 더했다. 그 뒤 반복되는 마음 문장 틀은 `tone-io.ts repeats`로 세어, 강의당 같은 틀 2번 이하·같은 문장은 과목 안에서 1번이 되게 슬라이드 내용에 붙은 말로 바꿨다(기준은 GUIDE의 "마음 문장에 변주 주기"). `scripts/tone-io.ts`로 글만 꺼내 고치고 넣으며, import가 수식·코드·숫자·`>` 인용·`보충:` 문단을 원문과 대조해 하나라도 다르면 막는다. 앱 화면 문구도 같은 말투다.
- Markdown은 remark-gfm(`singleTilde: false`, "0~9" 같은 범위가 취소선이 되지 않게)과 remark-cjk-friendly(`**용어 (abc)**이다`처럼 굵게 뒤에 한글 조사가 붙어도 닫히게)로 읽는다. 검증기도 같은 설정으로 깨진 굵게를 잡는다.
- 2026-11-02 오빠 요청으로 앱 안에서 슬라이드에 직접 필기하고(크게 보기의 필기 모드), 책갈피 아래 별표(켜면 빨강)를 달 수 있게 했다. 필기는 SQLite `ink` 표에 쪽·바탕 이미지(`clean` 올해, `prev` 작년 자료)마다 획 목록(JSON)으로 두고, 좌표는 이미지 너비·높이에 대한 0~1 비율이라 화면 크기와 상관없이 같은 자리에 그려진다. 획 모양은 perfect-freehand로 만든다. 화면 쪽 저장소는 `web/src/inkStore.ts`(강의마다 한 번 받고, 쓴 쪽만 0.5초 모았다가 PUT, 창을 떠날 때 keepalive로 마저 보냄), 그리는 면은 `web/src/Ink.tsx`. macOS 파일 시스템은 대소문자를 가리지 않아 `ink.ts`와 `Ink.tsx`를 같이 두면 tsc가 깨지므로 저장소 이름을 `inkStore.ts`로 뒀다. 별표는 `slide_state.starred` 열(옛 DB는 서버가 켤 때 열을 더함). 서버를 다시 띄워야 새 표와 API가 생긴다.

## 작업 규칙

- 해설 pack을 만들거나 고칠 때는 `content/GUIDE.md`를 따르고, `bun run validate`로 오류가 0개인지 확인한다.
- 원본 자료는 `../<과목 폴더>`에 있다. `.orig.pdf`는 원본이고 `.pdf`는 pdfnote 필기본이다. 원본 자료는 수정하지 않는다.
- `data/`는 `bun run extract`로 다시 만들 수 있다. 진도 DB `data/study.db`만 지우면 안 된다.
- 디자인 토큰은 `web/src/styles.css` 맨 위에 있다. 빨강 `#e11d48`과 파랑 `#2563eb`은 pdfnote의 펜 색이다. 폰트는 로컬에 설치된 경기천년제목과 경기천년바탕을 쓴다.
